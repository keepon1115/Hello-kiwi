# Hello Kiwi 英会話|会員エリア(Phase 1)実装指示書 v2

あなたは Hello Kiwi 英会話の既存 Next.js サイトに「会員エリア(マイページ)」を増築するエンジニアです。
この指示書に書かれていない判断が必要になったら、勝手に進めず必ず質問してください。

---

## 0. プロジェクト背景(必読)

- Hello Kiwi 英会話は、NZ育ちのバイリンガル講師による初心者向け英会話教室(近鉄八尾・対面中心+オンライン)
- 生徒層:小学生/その保護者/50〜60代の大人
- 教室のUSPは「個人個人のオリジナルレッスン」。会員エリアはこれを可視化する装置であり、**生徒一人ひとりが"自分だけの絵本のページ"を持つ**というコンセプト
- 世界観:「野原(field)に置いた絵本のページ(page)」。クリーム×キウィ×丸み×絵本感
- 宿題は Quizlet(外部)、連絡は LINE、予約はセレクトタイプ(外部)。**これらを置き換える機能は作らない。** アプリの役割は「レッスンとレッスンの間」を埋めることと、外部サービスへの分かりやすい導線

## 1. 既存リポジトリの前提

- Next.js 14.2.5(App Router)/ TypeScript / React 18 / Tailwind CSS 3.4
- カラーは `app/globals.css` の `:root` CSS変数が単一ソース。Tailwind は RGB トリプレット参照(`bg-orange/10` 等が使用可能)
- 各ページ = `page.tsx`(Server・metadata)+ `XxxClient.tsx`(Client・アニメーション)の分業。**この規約を厳守**
- 外枠は `components/SiteShell.tsx`。中央カラム `.site-main` は最大480px固定、`container-type: inline-size`
- **段組みは必ずコンテナクエリ(`@container`)で行うこと。ビューポート `@media` で段組みしない**(480pxで崩れるため)
- カラーの役割固定:オレンジ=行動 / グリーン=信頼 / イエロー=楽しさ。地=`--field` / 紙=`--page`
- `data-tone="adult"` をルート要素に付けると同5色がくすんだトーン(テラコッタ/セージ/オークル)に切り替わる既存機構がある
- 外部リンクは `lib/site.ts` が単一ソース。**予約URLもここに追加する**
- 実装前に `app/globals.css`・`SiteShell.tsx`・既存ページ数点を必ず読み、既存のパターン(Reveal、SectionHeading、Button、Accordion、ImageSlot等)を最大限再利用すること

## 2. Phase 1 のスコープ

作るもの:

1. 生徒別マイページ `/my/[token]`
2. 受講のきろく(日付+カルテ+**その日のスライド閲覧**)
3. キウィパスポート(スタンプ表示)
4. **回数券チケット(残数表示+日付スタンプ)**
5. **予約ボタン(セレクトタイプへの外部リンク)**
6. せんせいの声ポスト(音声再生)
7. NZたんけんカード
8. PWA対応(manifest + アイコン + ホーム画面追加の案内)

作らないもの(明示的にスコープ外):

- ログイン/認証UI(トークンURLが認証のすべて)
- 予約機能そのもの・決済・チャット・プッシュ通知(予約はセレクトタイプへのリンクのみ)
- 生徒からのアップロード機能(こえの宿題ポストは Phase 3)
- 管理画面(データ編集はリポジトリ内 JSON を直接編集する運用)
- Quizlet の学習機能の再実装(リンクのみ)
- 回数券の残数自動計算(残数はデータに書かれた事実のみを表示する。後述)

## 3. 認証方式:秘密URL(トークンリンク)

- 家庭ごとに一意のトークンを発行し、URL `/my/[token]` 自体を鍵とする。ログイン画面は存在しない
- トークンは推測不能な形式:`kw-` + 8文字以上の英数字(例 `kw-a7x2m9qp`)。生徒名を含めない
- 存在しないトークンは絵本トーンの「ページが見つかりません」(既存 not-found の世界観に合わせる)へ。**トークンの正誤がわかるエラーメッセージの出し分けはしない**
- `/my/` 配下は `robots.ts` で `Disallow` に追加し、各ページに `noindex` メタを付与
- 将来「あいことば」(1単語の合言葉)を後付けできるよう、データ側に `passphrase?: string` フィールドだけ定義しておく(Phase 1ではUI未実装)

## 4. データ設計(Phase 1 はリポジトリ内ファイル)

`lib/data/members/` を新設。将来 Notion API に差し替えるため、**ページコンポーネントから直接 JSON を import せず、必ず `lib/members.ts` のアクセサ関数(`getStudentByToken` 等)を経由**すること。

### 設計原則:1レッスン=1レコード

先生の運用負荷を最小にするため、「受講のきろく」「パスポートのレッスンスタンプ」「回数券の消化」は
**すべて `lessons` 配列から導出**する。先生がレッスン後に書くのは lessons への1エントリ追加だけ。

### students.json(生徒マスタ)

```jsonc
[
  {
    "token": "kw-a7x2m9qp",
    "displayName": "たろう",        // 表示名(ひらがな/ニックネーム。フルネームは保存しない)
    "tone": "kids",                 // "kids" | "adult" → adult は data-tone="adult" を適用
    "quizletUrl": "https://quizlet.com/...",  // 任意。無い生徒もいる
    "passphrase": null,             // Phase 1 未使用
    "startedAt": "2026-05",

    // ── 受講のきろく(1レッスン=1レコード。新しい順に表示)──
    "lessons": [
      {
        "date": "2026-06-12",
        "message": "今日は 'How are you?' にじぶんのことばでこたえられたね!",
        "tryThis": "こんしゅうは家族に 'Good morning!' と言ってみよう",  // 任意
        "slideSrc": "/assets/slides/kw-a7x2m9qp/2026-06-12.pdf",  // 任意。ローカルPDF/画像 or 外部URL(Canva等)両対応
        "countsForTicket": true     // 省略時 true。体験・振替などチケット消化しない回は false
      },
      {
        "date": "2026-06-05",
        "message": "はじめてのレッスン!",
        "slideSrc": "https://www.canva.com/design/xxxx/view"
      }
    ],

    // ── 回数券(月謝制の生徒は null → セクション非表示)──
    "ticket": {
      "label": "4かいチケット",
      "total": 4,
      "startDate": "2026-06-01"    // この日以降の countsForTicket なレッスンが消化対象
    },

    // ── パスポートの追加スタンプ(レッスン以外。宿題がんばった等)──
    "bonusStamps": [
      { "date": "2026-06-14", "type": "homework", "note": "しゅくだい パーフェクト!" }
    ]
  }
]
```

導出ルール(`lib/members.ts` に実装):

- **受講のきろく** = `lessons` を新しい順に表示
- **パスポート** = `lessons`(type: "lesson")+ `bonusStamps` を日付順にマージ
- **回数券の消化** = `ticket.startDate` 以降の `countsForTicket !== false` な lessons の日付を古い順に `total` 個のスロットへ割当。残数 = total − 消化数。**マイナスにはしない**(超過時は残0表示とし、consoleに警告)

```jsonc
    "date": "2026-07-01",
    "title": "Sweet as!",

    "audioSrc": "/assets/audio/voices/2026-w27.mp3",

```

### nz-cards.json(NZたんけんカード)

```jsonc
    "titleEn": "The kiwi is a flightless bird",
    "body": "ニュージーランドのシンボル…(2〜4文の日本語)",
    "emoji": "🥝",

```

### lib/site.ts への追加

```ts

  url: "https://select-type.com/rsv/?id=3spOTwJvnpQ&c_id=436907",
```

音声・スライドファイルは `public/assets/audio/voices/`・`public/assets/slides/[token]/` に配置。
未配置パスが指定されている場合は `ImageSlot` と同じ思想で「ファイル名つきプレースホルダ」を表示すること

## 5. 画面仕様

### 5-1. `/my/[token]` マイページ(このPhaseの主役)

構成(上から):

1. **あいさつヘッダー**:「たろうの ページ」+ マスコット(既存 `Mascot` を再利用)。`tone: "adult"` の生徒には敬体の文言(「〇〇さんのページ」)と `data-tone="adult"` を適用
2. **せんせいから(最新カルテ)**:`lessons` の最新1件の `message` をカード表示。`tryThis` があれば「こんしゅうの チャレンジ」として別枠に
3. **しゅくだい**:`quizletUrl` がある場合のみ表示。オレンジ(=行動色)の大きなボタンで外部リンク
4. **回数券チケット**:後述 5-2。`ticket` が null なら非表示
5. **よやくボタン**:`lib/site.ts` の reservation を使った外部リンクボタン。常設。位置はチケットセクションの直下(「残りを確認→次を予約」の動線)
6. **キウィパスポート**:後述 5-3 をページ内セクションとして表示(別ページにしない)
7. **せんせいの声ポスト**:最新1件を再生プレイヤー付きで。過去分は折りたたみ(既存 `Accordion` 再利用)
8. **NZたんけんカード**:最新1件をカード表示。過去分は横スクロールまたは折りたたみ
9. **これまでのきろく**:`lessons` を新しい順に。各レコード= 日付+message+(あれば)「この日のスライドをみる」ボタン。絵本の「ページがたまっていく」見た目を意識する

メタデータ:`title` は「マイページ | Hello Kiwi 英会話」固定(生徒名を入れない)。`noindex`。

### 5-2. 回数券チケット(セクション)

- 「きっぷ」や「スタンプカード」のモチーフ。`total` 個の丸いスロットを横に並べる(4個想定だが total に追従)
- 消化済みスロットには **🥝スタンプ+受講日付(MM/DD)** を表示。未消化スロットは空の点線丸
- 上部または横に「**あと ◯かい**」を大きく表示(adult トーンは「残り◯回」)
- **残り1回以下**のとき:「そろそろ つぎの よやくを♪」の一言を添え、直下の予約ボタンを視覚的に強調(色は変えず、サイズ/影/やわらかな出現アニメで)。**煽らない・急かさない文言にすること**
- 残り0のとき:「チケットが なくなったよ。つぎの チケットは せんせいに きいてね」+ 予約ボタン

### 5-3. キウィパスポート(セクション)

- NZのパスポート/スタンプ帳のモチーフ。lessons 由来のスタンプ+`bonusStamps` を月ごとにグルーピングして表示
- スタンプは type ごとに絵柄を変える:`lesson` = 🥝系スタンプ、`homework` = ⭐系スタンプ(SVGで自作。丸み・やわ影・絵本感)
- `note`/`message` があるスタンプはタップで一言表示
- **合計数の比較・目標達成率・ランキング的要素は一切入れない。** あくまで「自分の旅の記録」
- 新しいスタンプ(最新日付)には小さな「NEW」的アニメーション(既存 reveal の流儀に合わせ、控えめに)
- ※回数券チケット(5-2)とは役割が異なる:チケット=事務的な残数の事実、パスポート=旅の記録。見た目も分ける(チケットはきっぷ風、パスポートはスタンプ帳風)

### 5-4. スライド閲覧

- `slideSrc` がローカルPDF → 新しいタブで開く(`target="_blank"`)。モバイルでの閲覧性を優先し、Phase 1 ではビューア埋め込みは不要
- `slideSrc` が画像(png/jpg/webp)→ タップで拡大表示(シンプルなライトボックスで可)
- `slideSrc` が外部URL(Canva等)→ 新しいタブで開く
- ボタン文言:「この日の スライドを みる」(adult:「この日のスライドを見る」)

### 5-5. PWA

- `app/manifest.ts` を追加:`name: "Hello Kiwi 英会話"`、`display: "standalone"`、`theme_color` はクリーム(`#FAF5EA`)、`start_url` は `/`(トークンURLは各家庭で異なるため)
- アイコンは既存ロゴ/マスコットから 192px・512px を生成して `public/` に配置(素材が無ければ ImageSlot 同様プレースホルダ+ASSETS.md への追記で対応)
- `/my/[token]` ページ下部に「ホームがめんに ついか すると アプリみたいに つかえるよ」の小さな案内(iOS Safari / Android Chrome の手順をアコーディオンで)
- Service Worker によるオフライン対応は Phase 1 では不要(manifest のみ)

### 5-6. `/my`(トークンなしアクセス時)

- 「このページは 生徒さん専用です。LINEで届いた じぶんのリンクから 入ってね」という案内ページ
- 公開サイトへの導線と、体験レッスンへの導線(既存 CTASection 再利用)を置く → 未入会者が迷い込んだときの集客接点にする

## 6. デザイン原則(違反しないこと)

- CLAFT本体の craft 要素(テープ・傾き・ドゥードル)は**使わない**。まる角・やわ影・絵本感のみ
- 色の役割を守る:CTA=オレンジ、見出し・信頼=グリーン、楽しさのアクセント=イエロー。新色を追加しない
- 子ども向け文言はひらがな多め・分かち書き気味、adult トーンは敬体で漢字通常。文言はハードコードせず出し分け関数にまとめる
- フォントは既存(Zen Maru Gothic 系)をそのまま使う
- アニメーションは既存 Reveal の流儀に従い、控えめに。点滅・バウンドし続ける要素は禁止(シニア配慮)
- タップターゲットは最小44px。文字サイズは既存サイト基準以上
- 残数表示まわりで**不安を煽る表現・カウントダウン演出をしない**(広告的な圧は教室の哲学に反する)

## 7. 実装手順(推奨順)

1. 既存コードの読解(`globals.css` → `SiteShell` → `lib/site.ts` → トップページ → 既存コンポーネント)
2. `lib/site.ts` に reservation を追加
3. `lib/data/members/` のサンプルデータ作成(生徒3名:kids 2名 + adult 1名。うち1名は quizletUrl なし、1名は ticket なし=月謝制、1名は残り1回の状態にして強調表示を確認できるように)
4. `lib/members.ts` アクセサ+導出ロジック(チケット消化・パスポートマージ)実装。**このロジックには単体で確認できる簡易テスト(またはサンプルデータでの検証スクリプト)を付ける**
5. `/my/[token]` の骨組み(Server Component でデータ取得 → Client でアニメ)
6. チケット・パスポート・声ポスト・NZカード・きろく(スライド含む)の各セクションコンポーネント
7. adult トーンの適用確認
8. `/my` 案内ページ、not-found、robots/noindex
9. manifest・アイコン・ホーム追加案内
10. `npm run build` が通ることを確認

## 9. 質問すべきタイミング

以下の場合は実装を止めて質問すること:

- 既存コンポーネントの規約とこの指示書が矛盾しているように見えるとき
- globals.css に必要なトークンが見当たらないとき(勝手に新色を定義しない)
- チケット消化ロジックで想定外のデータ(startDate より古いレッスンだけ、等)に出会ったとき
- パスポート/チケットのスタンプデザイン等、複数案から選ぶ余地が大きいとき(ラフ案を2〜3出して選んでもらう)

## 10. 実装方針
形態:既存サイトに会員エリアを増築 + PWA化
新規アプリを別で建てず、いまの Next.js サイトに /my/... を足します。理由:デザインシステム・コンポーネント・世界観をそのまま流用でき、「サイトの絵本の続きに自分のページがある」という物語も一貫するからです。PWAマニフェストを足せば「ホーム画面に追加」でアプリとして振る舞います(ストア審査なし、更新即反映、費用ゼロ)。
認証:パスワードを捨てる
小学生とシニアにID/パスワードは事故のもとです。家庭ごとの秘密URL(トークン付きリンク)をLINEで1回送る方式にします。hellokiwi.com/my/kw-taro-x7f2 のようなリンクを開けばもう自分のページ。ログイン画面が存在しないのが最強の「使いやすい」です。カルテの内容は成績表ほどセンシティブではないのでこの方式で十分ですが、気になる場合は「あいことば」1語を後付けできる設計にしておきます。
データ:Phase 1はファイル、Phase 2でNotion

Phase 1:生徒データ・カルテ・カードはリポジトリ内のJSON/Markdown。しょういちろうさんがClaude(Code)と一緒に編集してデプロイ、という現在の開発フローそのままで運用できます
Phase 2:カルテとNZカードをNotionデータベースに移し、Notion API経由で表示。「レッスン後にNotionに1行書けばアプリに反映」になり、普段お使いのNotionが管理画面になります
Phase 3:こえの宿題ポスト(音声アップロードにSupabase Storage等が必要になる段階)

段階まとめ
Phase中身更新方法1マイページ・パスポート・声ポスト(再生)・NZカード・PWAJSONをClaudeと編集2Notion連携でカルテ運用を日常化Notionに書くだけ3こえの宿題ポスト(生徒→先生の音声)自動
